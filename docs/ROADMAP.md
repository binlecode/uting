## 记录在案的 NO

每条一个形状：**决定 · 理由 · 重开条件**。这三条是被提过又被拒的方向，再提之前先读；
机制与实测细节一律在 as-built 文档，这里只指过去。

- **打包 NO —— 公开，但不为分发打包。** 仓库以参考实现的身份公开（文档是更可传播的产物），
  不打包、无 installer、无 `v*` tag：支持面（`RESEARCH-tui-player.md` §4）大于差异化
  （`ARCHITECTURE.md`「六条发现」 第 1 条）。**重开 = 真的要单文件分发** —— 那要一个静态
  二进制，所以它开的其实是 Go 重写 NO。

- **两次被提过又被拒的扩面。**
  - **第三对引擎 NO** —— 不做喜马拉雅：`m` 端点要 `webtk` —— 每请求现算的令牌、住在 cookie
    jar 之外，"浏览器 profile → 导 jar → curl -b"在机制上够不到；只有 resolve 没有 search
    的不是引擎（ARCHITECTURE「八个平级动词」）。**死线索**（挡住重走）：换端点、参数八种组合、先取
    首页 cookie、补 `xm-sign`、真登录重导 jar、SSR —— 全试过。**候选网易云**：搜索半边
    验过（明文、零凭据、`fee` 在响应里），**resolve 半边没量过** —— 真开工第一步是量它
    （`RESEARCH-tui-player.md` §9 的气候是坏的）。
    **重开 = 喜马拉雅 `m` 侧不再答 `webtk缺失`**（上次实测 2026-08-28）。
  - **ut-search NO** —— `ut-search` 不做：它存在的理由只有 fan-out + 合并信封，砍掉即第二拼法
    （ARCHITECTURE「八个平级动词」 直接毙）；代价（第九个命令、冻结面上一种新信封形状）压过收益。
    **重开 = 第三对引擎落地** —— 先修三处把信封级 `engine` 当行 engine 的地方
    （`ut-playlist` 的 `results` 分支、`uting` 的 `build_all_rows` / `FOCUSED_PAYLOAD`）。

- **list= NO —— 一条 URL 里的 `list=` 不变成一个队列。** 与起播偏移同批提出、当场否掉，
  记在这里免得随那份 PLAN 一起消失。`&t=601s` 与 `&list=PL…` 长得像是同一类东西 ——
  都是链接里搭的一个 query 参数 —— 但它们不是一个量级：偏移是**一个数**，
  由引擎读出、由播放器交给 mpv 的一个 flag；`list=` 是把**一个句柄变成一份条目清单**，
  也就是一次分页的播放列表抽取、一份要塞进队列文件的记录数组，以及"清单变了怎么办"
  这个 `--queue` 今天不回答的问题。**重开 = 有人真的要它**，且第一步不是解析那个参数，
  而是回答清单的所有权：它是 `<engine>-resolve` 的一个新动词（像 `--parts`），
  还是 `ut-playlist` 的一次导入 —— 队列本身不是候选，队列是被消费中的播放列表
  （`AS-BUILT-player.md`「队列」）。

- **Go 重写 NO —— 不做 Go 版。** 差异化在契约不在渲染，而契约与语言无关
  （`ARCHITECTURE.md`「六条发现」 第 1 条）；single-binary 全有全无 —— 引擎永不移植（随外部
  网站变，shell 的原地可改性是净收益），于是 Go TUI 或 Go 播放器接 shell 引擎仍是
  四依赖，分发收益不兑现（「六条发现」第 2 条）；剩给移植的只有"删渲染负债"，买它要付一次
  生命周期语义与渲染器无法二分的回归风险。**Linux 不是理由**：mpv IPC 的硬卡点已由
  netcat 变体探测关闭（`ARCHITECTURE.md`「已知约束」）。同样不足以构成理由：流式搜索结果、
  每次按键 fork `stty`、带编译期保证的测试套件、bash 3.2/5 双版本矩阵、busybox-only
  环境。**两个重开条件**：真的要 MCP 那张脸（解除 `ARCHITECTURE.md`「定位与设计目标」 的那条非目标 ——
  领域证据与可抄的工程细节在 `RESEARCH-tui-player.md` §10），或 **打包 NO 反转** —— 单文件
  分发要一个静态二进制。哪一条成立，第一步都是冻结当时的契约（ARCHITECTURE「冻结面」）。

## 还没做的事（每条等着自己的前置）

- **B 站的一条搜索结果 ≠ 一个可播对象 —— 合集至少要标出来。** 实测搜"周杰伦"前三条全是
  数小时的长合集，这是该站音乐消费的主流形态而非 bug；分 P（`?p=N`）与"结果是专辑/歌单容器"
  是同一问题的另两种形态，三种一起解。这是**引擎的**活（correctness 加在下面）：由
  `<engine>-search` 在信封里说清，不让 `uting` 猜 —— 只在 TUI 加标记就是漏掉 agent 面的
  半个功能。**面已经在了**：行带必填的 `kind`/`access`（`AS-BUILT-contract.md`「数据契约」），
  但两个在产引擎都无信号可算、恒印 `track`/`full`（`AS-BUILT-engine.md`「`kind` 与 `access`」）。
  本条等一个带真信号的引擎 —— 网易云的 `fee` 是量过的那个。

- **B 站音频区（`au` 号）的歌词，走已有的字幕管线。** yt-dlp 的 `BilibiliAudioIE` 把
  `song.lyric` 作为 subtitles 暴露 —— 与 `yt-resolve --transcript` 同一条管线，届时
  `bili-resolve` 才长出 `--transcript`。**证据强度如实记：读源码得出、从未实跑**，
  开工第一步是拿真 `au` 号验证。前置：`bili-search` 只搜视频区，音频区的边界待答。

- **下载器** —— 唯一一个引擎必须参与的条目；它会不会把引擎从"解流"推回"完整客户端"、
  与 ARCHITECTURE「站点知识的边界」 的分界冲突，是开工前要先答的问题。

- **频道订阅** —— 套件里第一个不由用户按键触发的路径，需要周期性调度（launchd/cron）；
  与"不做常驻特权进程"（`CLAUDE.md`）如何并存是前置问题。
