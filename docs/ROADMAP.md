## 8. 决定

每条一个形状：**决定 · 理由 · 重开条件**。机制与实测细节一律在 as-built 文档，这里只指过去。
同主题的决定并作一条，**编号保留**（它们被各处引用，合并不迁移引用）。

- **D0 —— 定位冻结为 `ARCHITECTURE.md` §1**：agent 优先的媒体引擎（播放器 + 可插拔引擎对）+
  一张人脸；不做通用 TUI 播放器。音源数量不是定位的一部分；差异化那三件不受任何功能变更影响。

- **D1 / D2 —— 公开，但不为分发打包。** 仓库以参考实现的身份公开（文档是更可传播的产物），
  不打包、无 installer、无 `v*` tag：支持面（`RESEARCH-tui-player.md` §4）大于差异化
  （`ARCHITECTURE.md` §1.1 第 1 条）。**重开 = 走 §9 的单文件分发触发。**

- **D3 / D13 —— 契约是被冻结、被版本化的那个面。** 任何重写之前先冻结契约（**含引擎契约**）
  —— 它是唯一完整活过重写的东西，也是 Go 版的验收规格，整个写在 `AS-BUILT-contract.md`；
  semver 2.0.0 版本化的就是这个面、不是代码（公共 API 边界表与 bump 判法在同一文档开头）。
  0.y.z 期间：破坏性 → y，加法与修复 → z。**1.0.0 = D1/D2 反转那一天**，不是"感觉稳了"；
  tag 只在真发布时打；不设 CHANGELOG（那个事实已在 git log 里）。刻意排除的只有一处：
  `--get-url` / `--info` / `--transcript` 是引擎的动词，不是播放器的（`ARCHITECTURE.md` §13）。

- **D6 / D10 —— 名字：项目名 `uting`，命令按"谁在敲它"分，不留第二种拼法。**
  规则：人机面 = 发布名本身 · 播放器 = `ut-` 前缀 · 引擎 = 站名前缀（`yt-*` `bili-*`）·
  状态 = 前缀 + 存的那件东西的全词（`ut-playlist` / `ut-history`）。
  **不发任何短名**（六项筛查：长前缀可用、短名全被占，`RESEARCH-tui-player.md` §2），
  人机面因此也不叫 `ut-tui`。挡住重开的落选名：`ut-list`（与 `-l/--list` 撞车）、
  `ut-lib`/`ut-store`（两件事挤一个命令）、`ut-queue`（队列是播放器的运行时状态，
  `AS-BUILT-player.md` §9.5）。挪威语里 `uting` 是真词（"陋习"）—— 当彩蛋接受。

- **D9 / D11 / D12 / D19 —— 引擎边界，四条一致的切法。**
  - **D9** 套件按「播放器 + 可扩展引擎对」切，不按站点开命令：与音源无关的是播放器，
    有关的只有抽取；引擎 = search / resolve 两个动词，加音源只加一对脚本；resolve 发生在
    播放时（直链会过期，10 条结果只用 1 条）。形状 `ARCHITECTURE.md` §4/§5，
    契约 `AS-BUILT-contract.md` §3。
  - **D11** 引擎内部按「操作」选原语：B 站搜索走 curl（yt-dlp 那格实测走不通），解流走
    yt-dlp（自建 = 重造完整客户端）。数字在 `AS-BUILT-engine.md` §7。
    **重开 = yt-dlp 的 `BiliBiliSearchIE` 学会透传元数据**，那时本仓 HTTP 路径整个删掉。
  - **D12** resolve 只解自己站的 host，别的一律退 1（usage）：`engine` 字段的全部意义是
    路由，通配让它说谎。被否：通用引擎、引擎间委托。账：URL-only 音源接不进来；
    **重开 = 它们成为真实需求** —— 解法是写一对，不是放宽校验。
  - **D19** 按 site 切不按 stack 切：可共用的只有六行 `dump_once`，逐站不同的是 ~600 行，
    且 stack 会变 site 不会（`engine` 是被持久化的路由键）。八份样板的重复与 stack 正交，
    是"要不要共享库"那个独立问题。**重开 = 出现 resolve 半边与既有引擎逐字相同的音源。**

- **D14 / D15 —— 收听完整度在范围内，且在 shell 版做。** 队列、播放列表、收听历史服务于
  这套音源上的收听（收藏 = 一个具名播放列表）；不等 Go —— 刚需有时间成本而重写没有排期、
  难点是数据模型不是语言（shell 已有能用的状态层，`AS-BUILT-player.md` §9.2/§9.3）、
  先在 shell 跑顺则 Go 继承的是被真实使用过的规格。
  **硬约束（对以后每条功能同样成立）：必有 agent 面** —— 人有按键，agent 有动词 + `-j`，
  契约进 `AS-BUILT-contract.md`，回归进 `tests/`。历史默认开、`UT_HISTORY=0` 关；
  **重开 = 跑在共享账号上**（`AS-BUILT-player.md` §9.6）。

- **D16 / D17 —— 登录状态可见到"发不发"这一层，且住在 resolve 半边。** `auth=chrome` 说的
  是"播放会送 chrome 的 cookie"，不是"你登录着"（实测边界 `AS-BUILT-engine.md` §8.2）。
  被否两个：带凭据的探测往返（对限流 host 每次启动多打一发，答一个便宜事实已答掉八成的
  问题）；搜索信封加 `auth` 字段（两个引擎不对称 —— `bili-search` 一个凭据都不发，要报
  `chrome` 就得抄第 4 份 profile 判断副本）。**重开 = 有用户被过期会话上的 `auth=chrome`
  误导** —— 升级路径是加 `--auth --probe`，不改 `auth` 键的语义。

- **D18 —— 配置是一条四层链（flag > 环境 > 用户配置 > 出厂 `config`）；两个文件都按 DATA
  读、绝不 source；出厂那份永不被写，用户那份由 `uting` 写回六个偏好键。**
  理由：八个不共享库的可执行文件，"每个默认值声明一次"只能落到数据文件；source 会执行
  任意代码；一个每次会话都要重按的偏好等于没有偏好，而"设偏好"的 agent 面就是那个
  `KEY=value` 文件本身 —— 不为它造第九个命令（与 D21 同一笔账）。缺出厂文件 = 退 2。
  键表、写回约束、进公共 API 的部分，全在 `AS-BUILT-contract.md` §5。
  **重开条件**：出现第二种宿主形态时"出厂默认值是一个文件"可重开（链的顺序与命名空间
  不跟着重开）；出现第二个写入方时再谈写回的锁。

- **D20 / D21 —— 记录在案的两个 NO。**
  - **D20** 第三对引擎不做喜马拉雅：`m` 端点要 `webtk` —— 每请求现算的令牌、住在 cookie
    jar 之外，"浏览器 profile → 导 jar → curl -b"在机制上够不到；只有 resolve 没有 search
    的不是引擎（D9）。**死线索**（挡住重走）：换端点、参数八种组合、先取首页 cookie、
    补 `xm-sign`、真登录重导 jar、SSR —— 全试过。**候选网易云**：搜索半边验过（明文、
    零凭据、`fee` 在响应里），**resolve 半边没量过** —— 真开工第一步是量它
    （`RESEARCH-tui-player.md` §9 的气候是坏的）。
    **重开 = 喜马拉雅 `m` 侧不再答 `webtk缺失`**（上次实测 2026-08-28）。
  - **D21** `ut-search` 不做：它存在的理由只有 fan-out + 合并信封，砍掉即第二拼法（D10
    直接毙）；代价（第九个命令、冻结面上一种新信封形状）压过收益。
    **重开 = 第三对引擎落地** —— 先修三处把信封级 `engine` 当行 engine 的地方
    （`ut-playlist` 的 `results` 分支、`uting` 的 `build_all_rows` / `FOCUSED_PAYLOAD`）。

- **D4 / D5 / D7 —— Go 版（可选，§9）的三条预定。** 第一步只做 TUI，调用今天原封不动的
  引擎与 `ut-play`（否决一次性全量移植：生命周期语义和渲染器进同一次变更，回归无法二分）；
  播放器是否跟进是 §9 的独立触发决定，**引擎在任何情况下都不移植**（随外部网站变，shell 的
  原地可改性是净收益）；真做则只发一个二进制加子命令（`uting search / play / <engine> … /
  mcp`），**永不发布 `bin/yt`**（D10），per-engine 层的形状留到开工时定。

## 9. 把播放器推向 Go 的触发条件（可选项，非计划）

**Go 移植是 optional，不在任何排期上**：shell 版就是产品本体，`ut-play` 无限期保持 shell
是正当终态，不是等待状态。这一节存在只为一件事 —— 万一哪条触发真的成立，界定"值得移植的
是什么、代价怎么算"。（引擎在任何情况下都不移植，见 D5。）任一为真，**播放器**移植才值得
它的风险：

1. **真的要 MCP**（解除 `ARCHITECTURE.md` §1 的那条非目标）。同格竞争者给出了可抄的工程
   细节 —— `spotatui` 的默认关闭 + 只绑 loopback + token、双时代协议兼容、stdout 只跑协议、
   应用内与 MCP 复用同一张 tool table。2026-08 的领域证据两头都有
   （`RESEARCH-tui-player.md` §10）：agent 面已是标配，但除 `spotuify` 外全部只做"查" ——
   "agent 直接调 CLI"没有被谁证伪，MCP 依旧只是包装层。附带情报：`kevinwatt/yt-dlp-mcp`
   与 `--transcript` 正面重叠，B 站侧 MCP 服务器与 `bili-resolve --info` 同理 ——
   真做时要说清为什么用本仓的。
2. **真的要单文件分发**（推翻 D1）。

**Linux 不是触发**：mpv IPC 的硬卡点由 netcat 变体探测关闭（`ARCHITECTURE.md` §26），
主流发行版装一个带 `-U` 的变体即通。次要、单独不足以触发：流式搜索结果；每次按键 fork
`stty`；带编译期保证的测试套件；bash 3.2/5 双版本矩阵；busybox-only 环境。

## 10. 落地计划

**编号是标识，不是顺序。** 两条都是可选项（§9），今天都不动 —— 不动是正当状态，不是欠账。

- **P2 —— Go TUI 接 shell 播放器与引擎（D4）**：`bubbletea` + `lipgloss` + `go-runewidth`；
  移植**决定**而非代码（reflow 顺序、三个播放态、中英双语、扫 `*-search` 建注册表）；
  mpv socket 用 `net.Dial`。验收：对着 `AS-BUILT-verification.md` §27 与 shell TUI 并排比对
  （functional-only，无渲染 rig —— 用 `capture-pane` 的网格断言手动做）。
- **P3 —— 播放器移植（仅当 §9 触发）**：在冻结的契约背后重写 `ut-play`；引擎留在 shell，
  Go 播放器照样 `exec <engine>-resolve`。验收：固定查询集上两实现 `-j` 逐字段 diff +
  生命周期序列退出码全等，**两个引擎各跑一遍**。之后、且仅在之后：`uting mcp`、
  curl 安装脚本、Homebrew tap。

## 11. Future work（已蒸馏，等触发条件）

- **B 站的一条搜索结果 ≠ 一个可播对象 —— 合集至少要标出来。** 实测搜"周杰伦"前三条全是
  数小时的长合集，这是该站音乐消费的主流形态而非 bug；分 P（`?p=N`）与"结果是专辑/歌单容器"
  是同一问题的另两种形态，三种一起解。这是**引擎的**活（correctness 加在下面）：由
  `<engine>-search` 在信封里说清，不让 `uting` 猜 —— 只在 TUI 加标记就是漏掉 agent 面的
  半个功能。**面已经在了**：行带必填的 `kind`/`access`（`AS-BUILT-contract.md` §3），
  但两个在产引擎都无信号可算、恒印 `track`/`full`（`AS-BUILT-engine.md` §7.2）。
  本条等一个带真信号的引擎 —— 网易云的 `fee` 是量过的那个。

- **B 站音频区（`au` 号）的歌词，走已有的字幕管线。** yt-dlp 的 `BilibiliAudioIE` 把
  `song.lyric` 作为 subtitles 暴露 —— 与 `yt-resolve --transcript` 同一条管线，届时
  `bili-resolve` 才长出 `--transcript`。**证据强度如实记：读源码得出、从未实跑**，
  开工第一步是拿真 `au` 号验证。前置：`bili-search` 只搜视频区，音频区的边界待答。

- **下载器** —— 唯一一个引擎必须参与的条目；它会不会把引擎从"解流"推回"完整客户端"、
  与 D11 的分界冲突，是开工前要先答的问题。

- **频道订阅** —— 套件里第一个不由用户按键触发的路径，需要周期性调度（launchd/cron）；
  与"不做常驻特权进程"（`CLAUDE.md`）如何并存是前置问题。
