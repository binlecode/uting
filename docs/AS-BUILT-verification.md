# AS-BUILT-verification —— 风险登记与验证矩阵

这套套件**被什么证明**，以及**已知会在哪儿翻车**：设计层面的风险与它们的缓解，
以及验证矩阵 —— 每一个面由哪条检查覆盖、哪些东西**刻意没有**被覆盖。

**这份文档与 `ARCHITECTURE.md` 的分工**：架构文档只留图、流程、伪码与决定；证据链、测量数字与
证据在这里。节号沿用原有编号（**§25**、**§27**），所以既有的引用只需换文件名。
实现细节在 `AS-BUILT-player.md` 与 `AS-BUILT-tui.md`，契约在 `AS-BUILT-contract.md`。

**测量都带日期，且按设计会过期。** 一个没有日期的数字是一句不能被反驳的断言；
这份文档里的数字全都记着它是对着什么、在哪一天量的。

## 25. 风险登记（设计层面的缓解）

| 风险 | 缓解 |
|---|---|
| 删掉 TUI 之后留下悬空引用 | 删任何符号之前先用 grep 把它闸住 |
| `resolve_nc_unix` 的 ncat 分支在 macOS 上跑不到（本机 `nc -h` 有 `-U`，探测永远选 nc） | **如实记为无覆盖**：给 ncat 分支造覆盖要么 shim PATH（是 mock，规则禁止）、要么真上一台 Linux —— 后者才是补法。两个套件在 macOS 上验的是 nc 分支 + 探测函数本身的语法与惰性门（`playback.sh` 的活 socket 读走的就是它） |
| 标题里带 tab/换行会撑破一行 | jq `@tsv` 转义；`load_rows` 里 `IFS=$'\t'` 切分（如今是 US，见 `AS-BUILT-tui.md` §11） |
| 从渲染好的行里错误地还原 URL | url 与显示分开放在平行数组里（按下标取） |
| 过滤过度匹配 / 注入一个 glob | 纯 bash：`nocasematch` + AND 词元 + 加引号的 `"$tok"` |
| 把 URL 当查询粘进去 | `<engine>-search` 拒绝 URL → 不会阻塞式误播（ARCHITECTURE.md §3.2） |
| `uting` 在没有 TTY 时被跑起来（agent/管道） | 要求 `-t 0 && -t 1`，否则 die（不挂起） |
| 一次改名破坏兄弟定位 | 每个脚本解析自己的符号链接链（ARCHITECTURE.md §4）；步骤 B 先重指，步骤 C 才删 |
| yt-dlp 的 `ytsearch<N>:` 前缀被覆盖 | 字面量只在 `yt-search` 里，从不被改写 |
| 一个引擎的 URL 被送去另一个的 resolver（引擎被静默错标） | 每引擎一份显式 host 白名单 → 退 1，绝不返回一条解好的流（`AS-BUILT-player.md` §10、ARCHITECTURE.md §3.4） |
| 新增一个源需要改播放器或 TUI | 它不可能需要：播放器靠拼接引擎名找到 resolver（ARCHITECTURE.md §4），TUI 靠 glob 发现引擎对（`AS-BUILT-tui.md` §11） |
| 停止之后留下孤儿 mpv | 用进程组（pgid），不走 PID 树 |
| `set -u` 下的空数组展开（bash 3.2） | 用之前先守卫数组展开 |
| 有别的进程连上某个播放器的 IPC socket | `STATE_DIR/players` 0700；macOS 的 `$TMPDIR` 本就是每用户的（Linux 回退到 /tmp 时钉住权限） |
| pid 复用把一个死播放器误判为活的 | **收窄，未关闭**：句柄是单调 token、存活检查看 `<id>.json` 里存的 pid、记录在进程组消失时立即回收 —— 但 `group_alive` 仍是 `pgrep -g`，所以在那个窗口里一个被回收再用、且当上组长的 pid 会看起来是活的（`AS-BUILT-player.md` §9.3） |
| 被捕获的 `-d` stdout 阻塞在一个后台作业上 | detach 路径上已经没有后台作业：子进程从解析信封回填自己的记录（§9.1）。任何**未来**写在可捕获动词里的 `… &` 都必须重定向自己的 fd —— 一次命令替换等的是管道的**每一个**写者，不只是我们 |
| detached 的 mpv 状态行把磁盘写满 | `YT_DETACHED` → 子进程里 `--no-term-osd-bar --msg-level=all=error`（§9.1） |
| 搜索失败没给 agent 任何形状 | 捕获 stderr → `classify_yt_dlp_error` / `classify_http_error` → `{status:"error",…,reason}` 信封，退 2+（AS-BUILT-engine.md §7） |
| 一次风控挑战被报成一次零结果的**成功**（HTTP 200 + `code:0` + `data.v_voucher`，Bilibili 的第三种说"不"的方式） | `fetch_page_once` 趁响应体还在手上判券：券**且**没有 `result` 数组 ⇒ `PAGE_RISK` ⇒ `classify_http_error` 判 `network`（可重试）⇒ 重试一次否则退 2。三层都查，只读前两层的版本会返回 `count:0` 的 ok 信封（AS-BUILT-engine.md §7.1）。**这条覆盖不在套件里**：一张券没法按需产生，而唯一能产生它的东西是一个替身，那是这里不做的（§27） |
| 服务端的 `duration` 粗桶剪掉了 `-m/-M` 会留下的行（筛选改了**答案**而不只是**代价**） | 只在整个窗口落进一个桶时才下推 —— 要超集，绝不是更窄的切割 —— 而本地那对精确边界无论如何都照跑；`contract.sh` 用 `-M 600`（进桶）/`-M 601`（跨桶）这对判别性输入把两半一起钉住（AS-BUILT-engine.md §7.1） |
| 一条长得像 flag 的查询变成一个动作 | `--` 在**每一个**动词里结束选项解析，且每个动词在它之后重新施加自己的位置参数检查（ARCHITECTURE.md §6、AS-BUILT-contract.md §2） |
| 某个引擎发明一个新的 reason 值 | 那份枚举是 AS-BUILT-contract.md §3 的，且是封闭的；三个分类器实现它，谁都不许扩展 |
| 客户端在 `--status` 背后改了音量 | `--status` 从 socket 活读 volume，记录值只作兜底（`AS-BUILT-player.md` §9.3） |
| 并发的元数据回填与 set-volume 互相覆盖同一份 `<id>.json` | 按 id 的 `mkdir` 锁（`lock_player_state`）把两次 temp+mv 串行化；回填另外还做 pid 守卫（§9.3） |
| 写回把用户手写的配置改坏（丢注释、错开中文注释列、写下一个自己读不回来的值） | 就地改写只动匹配行 `=` 右边的值：键的空白、值与 `#` 之间那段空白、以及注释本身逐字节搬过去，**注释列刻意不重排**（宽度层住在渲染路径里，按字节补齐会错开中文注释，而文件仍然合法、什么都不报）；写下去的值必须过 round-trip 闸（`#`、引号、换行、首尾空白、开头 `~/` 一律拒）；先写临时文件再 `mv -f`，`cp -p` 在前，所以一个 600 的文件回来还是 600；`mv` 的目标是**沿 symlink 链解析之后的真实路径**，所以一份从 dotfiles 仓库链过来的配置不会被换成普通文件、留下一个被架空的原件（`AS-BUILT-contract.md` §5「写回」）。判别性输入在 `contract.sh` 的 TUI 段（§27） |
| 跑一次测试套件就改掉开发者自己的配置 | 三个调用点各自隔离（`contract.sh` 通篇一个空的临时文件、TUI pane 另有一个自己的、`drive.sh` 一份副本、`capture-pane` 一个自己的），**外加一条不靠任何人记得的守卫**：`contract.sh` 在两个出口各断言一次用户真实配置的 `cksum` 没变（§27） |
| 一个被环境变量压住的键被写进文件，然后每次启动被读到又扔掉 | 在读配置**之前**记下八个键里哪些已经在环境中；对这些键，写回变成 no-op 加一行提示（`AS-BUILT-contract.md` §5、ARCHITECTURE.md §3.6） |
| 一个凭据头到达 mpv 的 argv（在 `ps` 里可见） | 引擎不得把 `Cookie`/`Authorization` 放进 `http_headers`；写在 §8.1 与 AS-BUILT-contract.md §3 |
| mpv 被 SIGKILL 之后留下陈旧 socket | `[[ -S sock ]]` 测试 → `ipc_failed`，绝不挂起 |
| 对端不关连接时 `nc` 会等满 `-w1`（一个卡住的 mpv，不是健康的那种） | `request_id` 过滤 + `head -1`；一个**健康**的 mpv 在半关闭时就收，所以一次调用约 0.016s。`uting` 的重绘路径是一个紧循环，所以它根本**不等** `nc`：它从一个进程替换里读回复、读到最后一条就 break，这也把"卡住"那种情形也框住了 |

## 27. 验证矩阵

**上一次运行 —— 这是一次测量，按当次运行填进来的，不是一个要维护同步的常数。** 每个套件都在
最后一行打印自己的计数，那是那个数字唯一的家；这里的条目记录的是某一次运行在某一天花了多少，
它**按设计会过期**，而不是靠漂移过期。*2026-08-30，三个都绿*：
`contract.sh` **278 ok / 0 failed / 100s**，其中 `--offline` 那一半 **193 ok / 18s**、
零网络调用；`playback.sh` **47 ok / 0 failed / 68s**，之后 `pgrep mpv` 为空。
**那 68s 里没有一秒是猜的**：约 30s 是七次真实的引擎解析（`ut-play` 自己量到的换曲中位数 4.3s），
约 19s 是收听日志那一段把一首 19 秒的曲子**放到它自己的结尾**——这两半在"没有替身"这条规矩下
都不可压缩；余下的浮动是网络的，不是这个文件的。那几段等待是**有界轮询**而不是固定 `sleep`（见那个文件的门口）：
一个固定的猜测在机器只是慢的时候也会变红，而一次不是 bug 的红，仍然要有人去查一遍。*上一轮的数留在这里当网络方差的证据*：`contract.sh` 2026-08-25 当晚
五次运行落在 81–109s，同一个文件、同一批检查。

**这两个数字各自的成分**（计数本身在上面，只说一次）。`contract.sh` 如今**先跑离线那一半**，
而且能只跑那一半（`--offline`）：实网那一半约 77s（93 − 16，同一次运行相减），其中 tmux 那一段约 16s
——它从 4s 涨上来，涨的那 12s 是写回检查自己按下的两次重取（`→` 越过末页与 `o`）。
（那 16s 是同日、过滤那条检查落地**之前**量的；它一次数都不取，最多再花一秒。）
flag 门在 1s 变红、空闲生命周期 1s、死亡记录 2s。那 13 秒里有 5.5s 是播放列表存储对着一个
**活着的**持锁者刻意的自旋 —— 旁边那条陈旧锁检查只花 0.1s，因为陈旧判定挪到了自旋**之前**
（AS-BUILT-player.md §9.4）。

这个顺序在文件里是作为**契约**陈述的，因为其中一部分是承重的
（离线在前；死亡记录夹具，然后 TUI 段放最后，因为 pane 里的 `uting` 会轮询 `--status`
而每一个生命周期动词都回收）。`tests/` 下**三个**入口点全都把 `TMPDIR` 指向自己的目录 ——
两个套件加 `drive.sh` 驱动器，后者是最后一个还在用用户目录的 —— 所以它们没有一个够得到
用户正在听的那个播放器的状态目录。两个套件也把 `UT_STATE_DIR` 指向自己的：
一个 detached 播放器每首曲目写一行收听记录（`AS-BUILT-player.md` §9.6），
没有它的话每次运行都会往用户真实的历史里追加一打没人听过的曲目，
而历史与播放器不同，不是 `--stop` 收得回来的东西。`drive.sh` 刻意**不**重定向 `UT_STATE_DIR`
—— 从它截下来的一帧应该显示一个人看得见的那个存储 —— 改为给 pane 喂 `UT_HISTORY=0`，
在不清空**读**的前提下压住**写**。

**配置文件是同一条规矩往外一层，而它是随写回一起才变得承重的。** `uting` 如今会把八个键
写回 `UT_CONFIG` 指的那个文件（`AS-BUILT-contract.md` §5），于是"跑一次套件"从**读**开发者
自己的配置变成了**改**它。三个调用点各自隔离：`contract.sh` 通篇 export 一个空的临时文件、
TUI 段另给 pane 一个自己的、`drive.sh` 把用户那份**复制**进本次运行的临时目录
（读的一侧照旧是人看得见的那份，写的一侧落在副本上 —— 与 `UT_HISTORY=0` 同一笔交易），
`capture-pane` 那一处同样自带一个。**但三处各自记得 export 是靠不住的**，尤其是那个不走
`drive.sh`、自己起 TUI 的抓帧流程，所以真正的保险是一条守卫：`contract.sh` 在开头记下
用户真实配置的 `cksum`，在两个出口（`--offline` 与全跑）各断言一次它没变。
它抓的是**任何**漏网的调用方，包括这行字写下之后才加进来的那个；文件不存在时它报 skip，
不报绿 —— 一台没有配置可毁的机器，证明不了一台有配置的机器上的任何事。

**只做功能测试，且只有两个文件。** 渲染器 rig（`tui_pane.sh`）与它那个单元格网格证明器被移除了：
**版式是在一帧进入文档时被证明的**（`.claude/skills/capture-pane`，它仍带着 `assert_pane.py`），
而套件断言的是**存活** —— TUI 起来了、扛过两次 resize、按 `q` 以 0 离开。
唯一的例外是那次**往返**（`h` 打开日志、再按 `h` 回到搜索），它断言的不是画面而是**行源**：
表头上 `items=` 与 `results=` 的差别是一个状态，不是一幅版式。

**写回与两条边是同一条规矩下的新覆盖：断言的是文件的内容与表头上的一个数，不是画面。**
它们全挂在 TUI 段**已经起着的那一个** pane 上 —— 不多一次冷启动、不多一次冷搜索，
这正是 harden-before-you-extend 的样子。每一条各自带着它的判别性输入：

- `v` 之后，配置里那一行的**值**变了而行尾注释还在 —— 一个 `printf '%s=%s\n'` 的天真实现
  过得了值那一半，过不了注释那一半；
- 那个夹具**本身是一条 symlink**，指向另一个真实文件：`v` 之后它**仍然是** symlink，
  而变了的是链接指向的那份。这一条是零成本白捡的判别性 —— 一个 `mv -f` 到链接上的实现
  值那一半照样发绿（新的普通文件里就写着新值），只有 `-L` 这一问把两者分开；
- `f` 之后配置里**长出**了 `UT_PLAY_QUALITY=medium`，而夹具里原本没有这个键 ——
  `v` 那一条只证了就地改，追加是另一条路径。它带两个判别性输入：状态行在按之前被
  grep 过一遍且**必须没有** `quality=`（`auto` 不印，一个把每一档都印出来的实现过得了
  后面那半、过不了前面这半），而写下去的值是 `medium` 而不是 `auto` —— 出厂 cycle 是
  `auto medium high`，一个从头开始转的实现会写 auto 并在这里红；
- `→` 越过末页之后 `results=` 涨了，`←` 之后它回到 20，再按几次仍是 20 ——
  只加不减的实现红在第二步，没有地板的实现红在第三步（它会走到 0）；
- 那个数落在 `UT_START_RESULTS` 里，而**不是**落在步长键 `UT_FETCH_BATCH` 里；
- 被环境压住的 `UT_SORT_FIELD` 在按下 `o` 之后屏幕上说了一句，而文件里**从来没有长出**
  那个键。判别性在于**环境与文件取不同的值**：让两者取同一个值的写法，是一条在
  "这个 bug 不可能发生"的配置下发绿的检查；
- 过滤开着时按 `→`，行数**不**变。这一条是**先红后绿**的那种：`/` 打 `zzz`（零匹配）
  再按 `→`，在守卫落地之前真的多取了 20 行并丢掉过滤（2026-08-29 实测）——
  `filter_live` 的方向键分支调的就是 `move_selection`，所以 `more_results` 里那句
  "这里不可能有过滤开着"是断言不是事实。零匹配正是判别值：一个不设防的边会把 0
  换成一整套重新取回来的行。它等的是一个**标记**而不是一段猜出来的时间 ——
  紧跟着发一个 `Esc`，退出过滤时回来的那个数就是答案（没取数是 20，取了是 40）。

**`--parts` 与 `--quality` 是同一批进来的新覆盖，断言的都是"门"，不是抽取。**
十三道 contract 检查（2026-08-29，随 P2/P3 落地）：

- 能力规矩的两面都钉住，且钉的是 stderr **措辞**：`bili-resolve --parts` 在
  无句柄下退 1 说"需要 handle"（同一个调用同时就是别的引擎的**探针**），
  而 `yt-resolve --parts` 退 1 说"unknown flag"—— 一个引擎没有那个动词，
  就让它**以"没有"作答**，而不是发布一个永远答"没有"的动词；
- `--parts` 拒绝 `-f` / `-S`（枚举 parts 不解析流，与 `--info` 同一条规矩）、
  拒绝第二个句柄、拒绝 `--quality`；`--quality` 是流格式选择器，门在**入口**：
  bogus 档在 ut-play 门口退 1（在任何依赖门之前）、无句柄退 1、
  引擎门还在（`--engine nope` 照样先拒）、两个搜索半边都拒 `--quality`、
  `UT_PLAY_QUALITY=bogus` 在 uting 里启动即 1（空值读作 auto 的那条反方向）。
- `playback.sh` 那两条证明档位**真的到了引擎**：`--quality low` 的 detached 播放
  位置从 0 往前走（一个没被转发的档位会让这个数字停在 0）—— 门全绿只证明
  "没被拒"，这两条证明"被用了"。

**`selected` / `selected_resolution` 的三条（2026-08-29，随 P13 落地）断言的是"答案 ≠ 请求"。**
两条在 `contract.sh` 的实网半边、一条在 `playback.sh`：

- 两个引擎的解析信封里，`selected` 是**非空字符串且不等于 `format`**。判别值就是那个不等号：
  一个把请求回声进 `selected` 的引擎（键名读下来最顺手、也最省事的那个错实现）能过掉
  "有这个键"、能过掉"是字符串"、能过掉两个引擎的键集一致 —— 只在这里红。
  两条都读**已经在手里**的那两份信封，所以这项覆盖**一次往返都不多花**；
  把它推广到第三个引擎的是紧挨着的那条键集一致检查，任何一边缺键都在那里红。
- `playback.sh` 里，真播一条之后 player record 的 `selected` 是字符串。
  这一条**离线够不着**：记录出生时就是 `selected:null`，只有一次真解析会把它换掉，
  所以"回填丢了这个键"与"还没回填"在离线下长得一模一样。

**`i`、前方队列与在播的 engine 是 P5 的三批新覆盖（2026-08-29/30），断言的是门、取数与投影 ——
不是画面。** 卡片长出来的三样东西（前方队列块、meta 行的 `selected` 字段、卡内 `i` 叠上的那一行）

**P10 / P11 / P12（退役 `p`、补上 `j`/`k`、键位提示分两档，2026-08-30）加了十条，
而每一条都点得出一个既有检查抓不到的生产故障。** 计数因此从 268 / 191 走到 278 / 193：

- **离线那两条是一次*加固*，不是一个新文件。** 原来只有一条 `UT_PLAY_QUALITY=bogus dies in
  uting`，而它有两个毛病：它只驱动一道门，可那些标量旋钮**各是各的 `case`**（不像四个
  `*_CYCLE` 走同一个 `validate_cycle`），所以一道从没关上的门在它下面是绿的 —— `UT_KEYS`
  正是以那个形状到达的；而且它断言的是**退出码**，可这些全退 1，同一个文件里几行之后的
  TTY 闸也退 1，于是它分不清"拒了这个值"和"拒了这根管子"，也就**不可能红**。改成一条
  跨 `UT_PLAY_QUALITY` / `UT_KEYS` / `YT_BG` 的循环，断言的是**那句话点没点名那个键**。
- **tmux 面上的八条**，全部挂在 TUI 段**已经起着的那一个** pane 上，且全部读同一个东西：
  提示块 —— 全应用唯一一个把键写下来的地方，所以"档位没过滤"和"档位过滤掉了一切"在这里
  都看得见。判别性标记是 `9/0 volume`：这个拼法**只在列表块里**出现（卡片缩写成
  `9/0 vol`，`S_VOL` vs `S_VOL_ADJUST`），而一个没有播放器的面上别处两者都不印 ——
  于是一次 grep 同时说出"现在是哪一档"和"现在是哪个视图"。
  - `p` 因此是靠**它后面那个键**断言的，与再往下那条 `c` 骑在 `h` 上同一个手法：一个仍然
    切视图的 `p` 会把**卡片**摆上来，那么接着的 `?` 打开的就是卡片那个块，轮询等到的
    永远不是 `9/0 volume`。第二条证人（`NOW PLAYING` 一次都没出现）跟着同一次抓取读，
    不多花一次等待。
  - **写回两个方向都断言**：夹具里没有 `UT_KEYS` 这一行，所以它只能**追加**（与第七个键
    `UT_PLAY_QUALITY` 同一条判别）；而一个写了一次就不再写的实现，会让文件停在 `full`、
    屏幕却已经回到 `core` —— 所以回程那次也断言。
  - **`j`/`k` 的标记是翻页**：这个几何下一页 10 行、手上 20 行，所以十次 `j` 之后第 11 行
    出现，而一个根本没移动游标的 `j` 造不出这一行；它同时证明这两个键落进了 `move_selection`
    **本来那两条臂**，而不是一条忘了翻页算术的新臂。回程也断言 —— 一个绑反了方向的 `k`
    会把面留在第 2 页，而只看去程的那一条仍然是绿的。
- **不进套件的**：两档在窄面上各占几行、`?` 那一格落在哪一行 —— 版式，归 `drive.sh` 与
  capture-pane（实测记在提交信息里：100x30 core 一行 / full 三行，62x20 core 两行 /
  full 五行；条目卡、空卡、在播卡三个块各驱动过两档）。

**有两条检查被写出来、被盯着看、然后被撤掉 —— 记在这里是因为登记册就是覆盖率决定该待的地方，
也因为一条撤掉却不留痕迹的检查会被重新加回来。** 两条都栽在同一场考试上：*它没法被弄红。*

- **`live_props` 里那个 `head -n <count>` 的管道关闭**（`AS-BUILT-player.md` §9.3）。
  对着真实对端它不可能失败。把 `head` 换成 `cat` 再跑，两边都量到 **0.04 s**，
  所以一条对它的时序断言无论代码怎样都会通过。那道守卫看起来省下的 1.11 s，
  量的是一个*脚本化对端*的空闲计时器 —— 这套套件里没有替身，所以那个数字没有来源。
  守卫作为防御留在播放器里，但不配一个假装套件证明过它的绿钩。
- **一条被停止的队列不立墓碑。** 把子进程那个 `stopped` 分支整个禁掉，`failed[]` **仍然**是空的，
  所以这条检查对着坏掉的代码也是绿的。这个主张改住在它能失败的地方：
  `contract.sh` 用夹具驱动墓碑的边界（一次正常播完不写、一份没有墓志铭的日志不写），

> **观察到的抖动 —— 共享状态那一条已 CLOSED，这里是它的记录。** 2026-08-23，三次运行里的第一次
> 有十条检查失败，后两次以 78/78 原封不动通过；2026-08-24，同一簇在另一个窗口开着一个普通交互式
> `uting` 时红了两次，几分钟后什么都没改就 3/3 通过。机制比"两次运行重叠"更锋利：
> 死亡记录夹具住在 `${TMPDIR}/uting-$(id -u)/players` 下，只以 uid 为键，
> 而**每一个生命周期动词都回收** —— 于是从任何地方来的一次 `ut-play --status`
> （包括一个 TUI 的存活轮询）都会在墓碑夹具被创建与被读之间把它删掉。
> 持久的修法是每次运行一个状态目录，如今 `tests/` 下每一个入口点都建它：各自 export 自己的
> `TMPDIR`，于是同一个 uid 上不会有第二个 uting 共享这个目录。留下来的是同一个机制在**单次运行
> 内部**仍然隐含的那条**顺序规矩** —— 死亡记录段必须排在 TUI 段之前，因为 pane 自己的
> `--status` 轮询会回收 —— 而它写在那一段自己身上，不是靠版面顺序碰巧成立。
>
> **第二条已经追平，且它是一条真实的种族条件而不是环境问题。**
>
> **第三条，观察到两次、且仍未定位 —— 记下来是因为一条没被记录的抖动，是一条第二次没人认得出的
> 抖动。** 2026-08-25，两次背靠背运行的第一次里，TUI 段最后两条检查一起红了 ——
> *"quits on q with 0"* 与 *"hands the tty back on exit"* —— 而第二次以 177/177 原样通过。
> **这一对一起失败正是那个信号**：第二条读的那行 FLAGS 是由打印 `RC=` 的同一条 pane 命令打出来的，
> 所以两者都没出现，意味着 `uting` 在轮询允许的 10 秒内没有离开。它不是"退出很慢"：
> 事后量过，七次运行（三次朴素、四次照着该段精确的 boot → 62x20 → 26x24 → `q` 序列驱动），
> **每一次退出都落在 186–250 ms**，也就是说预算是成本的五十倍。两个可能吞掉按键的应用内机制
> 找过并排除了：`$TMUX` 设置时会跳过 OSC 11 背景查询（AS-BUILT-tui.md §11），
> 所以读取器里不可能坐着一个终端回复；而 `q` 不是 UTF-8 首字节，所以 `utf8_complete` 吸收不了它。
> 剩下的是这台机器：那天下午这个 checkout 上还有第二个会话在工作、也跑过同一个套件，
> 而两者有没有重叠没有被记录下来。作为**未定位**归档，附带那次测量，而不是解释掉。
>
> **它在同一天傍晚又发生了 —— 同样那两条检查、同样是两次运行的第一次、第二次干净 ——
> 而这一次它留下了东西。** 那次运行之后七分钟，一个

**四件这个套件刻意没有的东西，记下来，好让每一件都是被有意拒绝的、而不是被反复重提。**
没有一件是缺口；每一件都是一个带理由的决定：

- **不加 `tests/lib.sh`。** 两个套件互相独立、各自能单独跑通是**设计**，不是意外，
  而 CLAUDE.md 的"no rig layer"直接管着这里。重复的是大约二十行 `report`/`ok`/`bad` 的账房代码，
  可以接受；而重复的**论证**不可以 —— 这正是 `TMPDIR` 那套理由**只说一次、被指两次**的原因。
- **不加 `tests/all.sh`。** 两条命令，而 CLAUDE.md 已经写明各自什么时候跑：
  `contract.sh --offline` 每次提交前、完整的 `contract.sh` 每次推送前，
  `playback.sh` 播放器改动时。
- **不加"跳过网络"的环境**变量**开关** —— 环境变量是给 set-once 调优用的，而"跑不跑网络"是
  一次**每次调用**的选择，那是 flag 的形状（CLAUDE.md 的分法）。而 flag 是有的
  （`tests/contract.sh --offline`），理由三条：(a) 离线/在线那条边界**本来就是承重的**
  （就写在这个文件的段序契约里），而一条谁也停不下来的边界，只有作者一个人用得上；
  (b) CLAUDE.md 要求**任何改动**都跑这个文件，包括一次注释修订，而一个没有 YouTube
  就跑不起来的门，是一道大家学会跳过的门；(c) "你拿到的是哪一种绿"是靠**输出**答掉的，
  不是靠不给这个选项 —— `--offline` 是同一次运行的**前缀**（同样的检查、同样的顺序，只是在
  第一次实网调用前停下），停下的地方**点名**了没跑的是什么，而且提交/推送两级写进了 CLAUDE.md。
  实测：全跑 ~100s / 278 条；`--offline` ~18s / 193 条、一个包都不发。
- **不加只为抬高计数的检查**，也不加任何时序或渲染画面断言。加固的默认动作是让**既有的**
  那条更强，而不是多一个文件（CLAUDE.md 的 harden-before-you-extend）。

**这里刻意不按路径点名任何*临时*检查。** 例外是三个挣到永久位置、提交在 `tests/` 下的文件 ——
两个套件 `contract.sh` 与 `playback.sh`，以及 TUI 驱动器 `drive.sh`
（它什么都不断言，存在的意义是回收 session 被杀之后留下的 detached 播放器）——
根 README 按名字描述它们，因为**没有指针指向的东西，贡献者跑不了**。
此外这个套件用来验证过的一切，
都是一个仓库不跟踪的 `tmp/` 下的一次性东西（`.gitignore`：`**/tmp/`），
所以按路径引用它们是一个 checkout 兑现不了的承诺 ——
它只在恰好一台机器上解析得开，直到那台机器的 scratch 目录被清掉为止。
**耐久的是每条检查的*形状***，而下面的条目记的就是这个：驱动了什么、怎么观察的、
以及活下来的断言数。一条检查从描述重建很便宜，而当它点名的那个文件已经不在时去信任它很贵。
