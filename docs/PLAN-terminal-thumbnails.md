## 机制：`f=100` 只收 PNG，所以管线里有一步转码

kitty 协议规定终端只需理解**三种**格式 —— `f=24`（RGB）、`f=32`（RGBA，默认）、
`f=100`（**PNG，仅 PNG**）；协议的设计原则明写"不应要求终端理解图片格式"，
**转换是客户端的活**（出处见 `RESEARCH-terminal-graphics.md`「出处」）。
**而两个站点发的都不是 PNG**，所以这一步躲不掉。

于是管线多一步 —— 而承担这一步的仍然是**已有的依赖**：

```
  curl ──► 一个字节流 ──► mpv 解码 + 缩放 ──► PNG 文件 ──► base64 | fold ──► \e_G… f=100
```

**这与「图片不走 mpv 的 VO NO」不矛盾，方向正相反**：那条 NO 否的是让 mpv **画**
（它会清屏、抢鼠标上报、发未压缩帧）；这里让 mpv **解码**，输出是一个文件，
它一个转义序列都不发。同一个依赖，用在它擅长的那一半上。

**实测的量级（2026-09-01，320×180 一张真 YouTube 缩略图）**：

| 路线 | 转义序列载荷 | 4096 分块 | 什么时候付 |
|---|---:|---:|---|
| `mpv --vo=kitty`（那条 NO 否掉的） | 461,951 | 112 | **每一帧** |
| 转码 → PNG，原尺寸 | 170,888 | 42 | 每行一次（缓存） |
| **转码 → 缩到 192px 宽 → PNG** | **52,012** | **13** | **每行一次（缓存）** |

转码本身 **0.11s**（`time mpv … --vf=scale=192:-2 --vo=image`）。
**缩放不是省字节的小聪明，是正确性**：不缩的话就是把一张 720px 的图塞进 24×7 个格子，
让终端去降采样 —— 多传 3 倍字节买一次更差的缩放。

## 探过的四个形状，与选中的那个

| 形状 | 是什么 | 结论 |
|---|---|---|
| **S1 每行一张** | 列表里每一可见行左侧一张缩略图 | **否**。一屏 20 行 × 52KB ≈ 1MB **一次重绘**，而实时过滤是逐按键重绘；更致命的是行高：一行文本放不下一张图，行高变 3 就是把 reflow、分页、`PAGE_SIZE` 推导全部重写（`AS-BUILT-tui.md`「重排」） |
| **S2 焦点行一张，画在 detail 区右栏** | 选中行的封面，画在已有的详情块右侧（版面、预算闸与三个位置的取舍见「画在哪里：版面」） | **选中**。一次选择变化一张图，detail 区本来就是"变高、太矮就自己丢掉"的 chrome，挂在它身上是延用既有契约；图的生命周期只绑在"焦点"这一个变量上，是最少的状态 |
| **S3 独立的封面视图（一个新行源）** | 像 `c`/`i` 那样按键进入、再按退出 | **否**。行源模型的前提是"它产出行"（`AS-BUILT-tui.md`「一个视图五个行源」），一张封面不是行；为它开第六个行源是把模型撑坏来装不属于它的东西 |
| **S4 只做 agent 面，不画** | 引擎多一个 `thumbnail` 字段，TUI 不动 | **否，但它是 S2 的子集**。路线图的规矩是"每个特性都要带 agent 面"，不是"可以只有 agent 面"；而 S2 的第一步恰好就是 S4，所以它成了落地顺序里的 B 阶段，不是替代方案 |

```
 9  >  1. 1 A.M Study Session [lofi hip hop]              1:01:14
18    10. Chill Summer Lofi [chill lo-fi hip hop beats]    2:03:12   ← 10 行（被 config 封顶）

21  ─────────────────────────────────────────────────────────────
22    1 A.M Study Session [lofi hip hop]                            ← detail 区，4 行，
25    avatar now ...                                                   **变高**

```

**关键的一条**（`shell/uting:3515`）：`psize = min(UT_PAGE_ROWS, avail)`，
而 `UT_PAGE_ROWS=10` 是 `config` 里的出厂值。**列表是被配置封顶的，不是被几何封顶的** ——
所以在够高的终端上，detail 区下面那几行是**真空档**，用掉它一分钱不花。

### 三个位置，选中的是右栏

| 位置 | 是什么 | 结论 |
|---|---|---|
| **L3 列表右侧的常驻栏** | ncmpcpp / spotify-player 那个样子 | **否**。高度完全够（列表区几乎总有 ≥7 行），但它**对每一行永久收 26 列的税** —— 包括没有封面的行（两个存储的行源恒 `null`）。在 `drive.sh` 会跑的 62×20 上直接致命 |
| **L2 detail 区下方的空档** | 画在那 5 行真空档里 | **否**。空档大小取决于描述**折了几行**，于是上下箭头一走，封面就会出现、平移、消失 —— 正是本仓一贯拒绝的"抖" |
| **L1 detail 区右侧** | 详情文字让出右边 26 列 | **选中**，理由是本仓特有的：detail 区**本来就**被声明为"变高的 chrome，要多少占多少，终端太矮就整块丢掉"（`shell/uting:3370` 那段注释）。把图挂在它身上是**延用一条既有契约**，而不是新开一条 |

### 版面

```
21 ──────────────────────────────────────────────────────────────────────────
22   1 A.M Study Session [lofi hip hop]                       ╭──────────────╮
23   Lofi Girl · 1:01:14 · 135,388,559 views · lTRiuFIWV54    │              │

```

**靠右不靠左**：列表行的时长本来就右对齐在同一条竖边上，封面接在那条边下面是连续的；
而放左边会把详情文字整体推右，破坏它与列表 `  1. ` 缩进的对齐。

### 预算闸：只在**不花钱**的时候画

把 `detail_h` 顶到 7 行是有代价的，但只在矮终端上有。100 列下的实际算术：

| 终端 | 顶之前的 `avail` | 顶之后 | 列表行数 |
|---|---:|---:|---|
| ×30 | 16 | 13 | 10 → **10，白拿** |
| ×24 | 10 | 7 | 10 → **7，花掉 3 行** |
| ×20 | 6 | 3 | 6 → **3，花掉 3 行** |

**于是闸门是：`avail - (7 - detail_h) >= UT_PAGE_ROWS` 才画。**
约 28 行以上白拿，以下就悄悄不画、把行数留给列表。
这与 hint 块、detail 块**已有**的"终端太矮就把自己丢掉"是同一个动作，不引入新概念。
**注意闸门量的是列表预算，不是 detail 区自己的高度**：只问这块够不够 7 行的写法，
会在 24 行的终端上先把 3 行从列表里偷走，然后才发现不该画。

**宽度闸**：26 列的留白要求总宽 **≥ 76 列** —— 再窄，文字就只剩 34 列了。不足就不画。

### 两个必须写进实现的后果

1. **那 7 行必须计入 `detail_h`**，哪怕图是画在文字**旁边**的。
   不计入，重排就不知道这几行被占了，光标的停靠行会撞进图的下半截。
2. **有图无图，版面不变** —— 闸门开着但这一行没有 `thumbnail` 时，右栏留白，
   `detail_h` 仍然是 7。否则上下箭头一走，文字的折行宽度就会跳。

**格子长宽比 ≈ 1:2**，所以 24×7 = 1.71 ≈ 16:9 是对的；同比例的还有 20×6、16×5。
**不做这个梯子**：固定 24×7，由闸门决定画不画 —— 与已经定下的「不缩小」一致。

## 分层：谁拥有什么

```
  yt-search  ──► thumbnails[] ──┐
                                ├──► 行里的 thumbnail: "https://…" | null   （引擎的活）
  bili-search ──► pic ──────────┘

  uting ──► image_probe()      能力探测（终端答不答 TGP）
        ──► image_fetch()      curl 取字节流 → 缓存
        ──► image_transcode()  mpv 解码 + 缩放 → PNG          （渲染的活）
        ──► image_draw()       base64 | fold → \e_G… f=100
        ──► image_clear()      \e_Ga=d,i=<id>

  ut-play      不参与
  ut-playlist  不存 thumbnail
  ut-history   不存 thumbnail
```

**第一条尤其重要**：`uting` **不认识** `thumbnails[]`，也**不认识** `pic` ——
那两个是站点字段，认识它们就是把站点知识搬进 TUI（`CLAUDE.md`「站点知识只住在引擎对里」）。
规范化必须发生在引擎里，`uting` 只见到一个叫 `thumbnail` 的、可以直接 GET 的 URL。

**两个存储不存图**（评审已定）：`ut-playlist` 的记录是一次 CALL（`{engine, url, …}`），
`ut-history` 的行是它加四个字段。缩略图 URL 是 **CDN 上会过期的东西**，存下来就是存一条
注定会烂的数据，而这两个存储的全部价值在于**存下来的东西一年后还能用**。
**后果要接受**：从 `b`/`h` 进来的行源没有图，那一格空着 —— 诚实的降级，不是缺陷。

## 接口契约

### 引擎侧：精简投影 10 → 11 字段（加法，`VERSION` bump **z**，评审已定）

`AS-BUILT-cli-contract.md`「数据契约」的行 schema 增加一个键：

| 键 | 类型 | 语义 |
|---|---|---|
| `thumbnail` | `string \| null` | 一个可直接 GET 的图片 URL；引擎拿不到就是 `null`（**键必须在**，照"引擎不知道的字段是 null、键仍在"的既有规则 —— `bili-search` 的 `live_status` 是先例） |

**`yt-search`** —— **[已实测 2026-09-01]** flat 搜索条目**确实带** `thumbnails[]`，
且每项带 `width`/`height`（实测一条：360×202 与 720×404 两项）。选取规则写死在 jq 里：
**取宽度 ≥ 200 的最小一张**（显示框只有 ~192px 宽，更大的都是白传）；
都小于 200 就取最大的；数组缺失或全无 `url` → `null`。

**`bili-search`** —— **[已实测 2026-09-01]** `pic` 在实测的每一行上都是**协议相对**的
`//i0.hdslb.com/bfs/archive/<hash>.jpg`，所以**必须补 `https:`**；空串 → `null`。

两个引擎各自实现，**不共享代码**（八个独立可执行文件不共享库）。`-J` 不变。

### `uting` 侧：一个配置键，零个新按键

| 键 | 取值 | 出厂 | 说明 |
|---|---|---|---|
| `UT_IMAGE` | `auto` \| `on` \| `off` | `auto` | 在 `config` 里声明一次，走 flag > env > 用户 config > 出厂 的四级链 |

**键名 `UT_` 而非 `YT_`（评审已定）**：套件级的 chrome 键按 `CLAUDE.md` 的规矩就是 `UT_*`，
跟规矩不跟疤。**这条同时替 `ROADMAP.md`「强调色可调」那个"键名前缀先定"的前置作了答** ——
落地时要回去把那条的前置划掉。

**不加按键**：图跟着焦点走，没有"要不要看图"这个每次都要做的选择 ——
按 `CLAUDE.md` 的分法这是**设置一次的调优**，就该是配置键。

`auto` 的解析顺序（**每一步都可判别**）：

1. `UT_IMAGE=off` → 关，**一个字节都不发**。
2. `[[ -n "${TMUX:-}" ]]` → 关。**照 `YT_SYNC` 的先例**（DCS 帧同步 `auto` 在 tmux 下就是关的），
   理由同源：复用器要 DCS 透传，开了也常不通（`RESEARCH-terminal-graphics.md`「复用器」）。
3. `TERM=dumb` → 关。
4. 否则跑一次 `image_probe`；答 `OK` → 开，其余（含超时）→ 关。

`UT_IMAGE=on` **跳过第 2、3、4 步**强制开 —— 给"我在 tmux 里自己配好了 passthrough"
这个真实存在的用户。门：三值之外 → `die`，**退出码 1**，消息里带键名。

**agent 面（评审已定）**：`thumbnail` 这个字段**就是** agent 面 —— agent 拿到 URL
自己去取图即可。**不加 `--thumbnail` 动词**，那是同一件事的第二拼法
（`ARCHITECTURE.md`「八个平级动词」）。

## 核心处理逻辑

### `image_probe()` —— 照抄 OSC 11 的形状

本仓已经有一个终端查询，就在 `shell/uting` 的背景色探测里：发一段查询、
用 `read -rsn1 -t 1` **逐字节**收回复（bash 3.2 没有 `read -d`）、64 字节封顶、
在 tmux 下整段跳过、并把"一次未应答花 1 秒"这个代价写在注释里。**照抄，不要另发明**：

```
发：  \033_Gi=99,s=1,v=1,a=q,t=d,f=24;AAAA\033\\
收：  \033_Gi=99;OK\033\\        → 支持
      任何其它 / 超时             → 不支持
```

只在**启动时跑一次**，结果存进全局；不在渲染路径上重跑。
**启动代价**与背景色探测同级：最坏加 1 秒，且只在既非 tmux 又非 dumb 时发生。

### `image_fetch(url) → path` —— 不看 Content-Type

```
缓存目录：$UT_STATE_DIR/thumbs/
文件名：  <engine>-<id>.src        ← 行记录里已有的 engine 与 id，站点的稳定标识
取：      curl -fsSL --max-time 3 -o <tmp> "$url" && mv <tmp> <path>
```

- **文件名不用哈希**：bash 3.2 没有内置哈希，`shasum`/`md5` 的跨平台调用是又一个要养的分歧。
  行里已有的 `{engine, id}` 本来就是全局唯一的稳定键。
- **扩展名一律 `.src`，不按 URL 猜格式** —— 理由见下一节。
- 缓存命中就不取。上限 **200 个文件**，超了删最旧的（`ls -t` + `tail -n +201`），
  **在启动时裁剪一次**，不在渲染路径上做。
- 失败（超时、404、非 200）：**静默不画**，不报错、不重试；下次焦点回到这行再试。

### 不嗅探格式：一律交给 mpv（这就是"支持所有 mimetype"的实现）

**实测（2026-09-01）：YouTube 的缩略图 URL 以 `.jpg` 结尾，服务器返回的
`Content-Type` 却是 `image/webp`。** 扩展名是假的；而 Content-Type 也不必看。

```
image_transcode(src, dst):
    mpv "$src" --frames=1 --no-audio --vf=scale=192:-2 \
        --vo=image --vo-image-format=png --vo-image-outdir=<dir> --really-quiet
```

**mpv 解得了的就画得出来**（JPEG / PNG / WebP / AVIF / GIF 的首帧 / …），
解不了的就不画（`mpv` 非零退出 → 静默跳过）。**没有格式分支，没有嗅探，
没有一张要维护的 mimetype 表** —— 不认识格式，而是把认识格式的那个依赖用起来。

- **动图只画首帧**，而这不是一个特例分支：`--frames=1` 对所有输入都是同一行为。
  动画本身是非目标（要 `a=a` 多帧上传加第二个时钟）。
- 产物 `<engine>-<id>.png` 与源文件同目录、同裁剪策略；**转码只做一次**，之后命中缓存。
- `--vf=scale=192:-2` 的 `-2` 是"按比例算高度并保持偶数"，不写死高度：缩略图的宽高比
  两个站点并不一致（16:9 与 4:3 都出现过）。

### `image_draw(path)`

```
1. image_clear                        ← 先删掉上一张
2. \033[<row>;<col>H                  ← 定位
3. base64 < path | fold -w 4096       ← 实测缩到 192px 后是 13 块
     首块  \033_Ga=T,f=100,i=<ID>,c=<cols>,r=<rows>,q=2,m=1;<data>\033\\
     中块  \033_Gm=1;<data>\033\\
     末块  \033_Gm=0;<data>\033\\
4. 重新定位                            ← 把光标交还给渲染循环
```

- **`i=<ID>` 固定用同一个 id**：全程只有一张图在屏上，所以 id 是常量。
  它让 `a=d,i=<ID>` 能精确删掉自己那一张，而不是 `a=d` 删光所有图
  （那会把复用器里别人的图一起删掉）。
- **`q=2`**：让终端不要应答 —— 应答会掉进 `read_nav_input` 的按键流里，
  被当成用户按了几个键。**这一条是必需的，不是优化。**
- 尺寸 `c=24, r=7`（格），与 `scale=192` 对应。
- **这 7 行要计入 `detail_h`**（见「画在哪里：版面」）—— 图虽然画在文字旁边，
  但重排必须知道它占了行，否则光标的停靠行撞进图里。

### `image_clear()`

```
\033_Ga=d,i=<ID>\033\\
```

**这个函数是整条特性最容易漏的地方**：kitty 的图像**不会被 `\033[K` 或 `\033[J` 擦掉** ——
它不在字符网格里。它必须被显式调用，且**三处一个都不能少**：

1. **每次全屏重绘之前**（`\033[J` 那一处的紧邻上游）；
2. **退出的 trap 里** —— 与恢复光标、恢复 echo 同一个 trap
   （`CLAUDE.md` 的终端所有权规则：自绘的 UI 拥有整段会话的终端状态，就得在同一处还回去）；
3. **resize 之后**（重绘会重画，但旧图必须先删，否则新旧两张同时在屏上）。

### 什么时候画 —— 性能前提，不是以后再优化

**只在焦点稳定之后画，不在每次按键时画。**

- 焦点变化 → 置 `IMAGE_DIRTY=1`，**不画**；
- 已有的 tick 到来，且 `IMAGE_DIRTY=1`，且**没有待处理输入** → fetch + transcode + draw，清 dirty；
- 实时过滤逐键重绘期间：只 `image_clear`，不画。输入停下来才画。

理由算得出来：连按 `j` 翻十行，逐键画是 10 次 curl + 10 次转码（0.11s 各）+ 10 × 52KB；
tick 上画是 1 次。**这同时是"图不闪"的实现**：中间态根本没画过。

## 边界情况

| 情况 | 行为 |
|---|---|
| `UT_IMAGE=off` / `TERM=dumb` | 一个字节都不发。**不是"画了个占位"** |
| tmux 且 `auto` | 关（`YT_SYNC` 先例）；`on` 则照发，用户自负 |
| 行的 `thumbnail` 是 `null` | 不画。**布局不变** —— 有图无图占同样的空间，否则每次换行都在抖 |
| 行源是 `b`/`h`（两个存储） | 恒 `null`（存储不存图），走上一行 |
| `curl` 失败 / 超时 | 静默不画，不重试 |
| **mpv 解不了这个字节流** | 静默不画。**这就是"不支持的 mimetype"的全部处理** |
| **预算闸不过**（`avail - (7 - detail_h) < UT_PAGE_ROWS`） | 不画。**绝不从列表里偷行** |
| 终端宽 < 76 列 | 不画。**不缩小** —— 缩小要重取重转码（贵）或让终端再压（糊） |
| 闸门开着但这一行没有 `thumbnail` | 右栏留白，`detail_h` **仍然是 7** —— 版面不随行内容跳 |
| 终端 resize | `image_clear`，随重绘重画 |
| `q` 退出 / Ctrl-C / 被 kill | trap 里 `image_clear` |
| 起了后台播放（`-d`） | 无关，图不参与播放路径 |
| 终端答了 TGP 但实际是复用器在装 | 用户可见的失败是"图没出来"，不是崩溃 —— `q=2` 保证不会有杂应答污染按键流 |

### 非目标

- **动画。** 协议的动画要 `a=a` 多帧上传加一个自己的时钟，那是在一个自绘的单线程渲染循环
  旁边再开第二个渲染循环。首帧就够，而"够"是这个项目一直以来的判据。
- **只发 kitty 一种协议。** sixel 与 iTerm2 各是一套编码与一套探测；三套协议是三份要养的
  分歧，而本机 mpv 连 sixel 都没有（`RESEARCH-terminal-graphics.md`）。
  **不支持的终端就是不画** —— 兜底不是"画个半块马赛克"，那是又一个渲染器。

## 已定的五个决定（2026-09-01 评审）

1. **键名 `UT_IMAGE`** —— 跟 `CLAUDE.md` 的规矩，不跟 `YT_` 的疤。顺带替
   `ROADMAP.md`「强调色可调」的前缀前置作答。
2. **`thumbnail` 字段就是 agent 面** —— 不加 `--thumbnail` 动词。
3. **`VERSION` bump z** —— 加法不破坏既有调用方。
4. **两个存储不存 `thumbnail`** —— 代价是 `b`/`h` 的行永远没有图，接受。
5. **不做动画，但也不做格式分支** —— "支持所有 mimetype"的实现是**不认识任何 mimetype**：
   字节流一律交给 mpv 解码，解得了就画（含 GIF 首帧），解不了就不画。

## 开工前还剩的唯一一个前置

**A 阶段需要一台能开真 TGP 终端的机器**（kitty / Ghostty / WezTerm），
因为「退出后不残留」「`q=2` 不污染按键流」这两条**只能在那里证**，而本机
`TERM=xterm-256color`、且套件全在 tmux 里跑。**拿不到就不要开工** ——
这条特性的失败模式是"在用户的终端上留下垃圾"，那是不能靠推理放行的一类。
