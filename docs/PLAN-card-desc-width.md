## 1. 症状

TUI 列表视图按 `i` 打开条目卡片，卡片**写完顶部之后停 0.88 秒**才写下半截。
实测（2026-08-30，100x30，逐 0.1s 采样 tmux pane）：

```
0.01 → 2.66s   每 ~0.1s 变一次     ← 取数转轮（--info 网络往返，2.7s，正常）
2.76s          卡片顶部写出（标题/频道/上传日期/章节表）
               ↑ 整整静止 0.88 秒，进程在算宽度，什么都没往终端写 ↓
3.64s          卡片底部写出（描述块/mode 行/提示行）
```

**在 tmux 下这表现为一张"半截卡片压着旧列表"的撕帧**；在正常终端里不撕 ——
`display_menu` 把整次重绘包在 kitty 的 DCS 帧保持里（`shell/uting:3908`/`:3913`），
`SYNC_ON` 在非 tmux、非 dumb 终端下默认为 1（`init_sync`，`:945`）。
所以**撕帧不是这份计划要解决的东西**，0.88 秒的延迟才是。

---

## 2. 病根（读出来的，且已量化）

一条链：

1. `card_*` 渲染描述块时调 `truncate_disp "$ITEM_DESC" "$cut"`（`shell/uting:3654`），
   `cut = budget * CARD_TEXT_W`，`CARD_DESC_MAX=6`，`CARD_TEXT_W = cols - 4`
   → 100 列下 `cut ≈ 576` 格。
2. `truncate_disp` 的**第一行**是 `disp_w "$text"` —— 把**整段**走一遍，
   只为回答一个是非题：「这段是不是已经放得下 `max` 格？」
3. `disp_w` 有一条 ASCII 快路径，但它是**全有全无**的：

   ```bash
   if [[ "$s" != *[![:ascii:]]* ]]; then DISP_W=${#s}; return; fi   # 纯 ASCII → O(1)
   for ((i = 0; i < ${#s}; i++)); do char_w "${s:$i:1}"; ...        # 否则逐字符
   ```
4. 那条描述 **3621 个字符，非 ASCII 只有 54 个**（`🎼 🎭 🌎 👕 💬 🎨`，Lofi Girl 用来分段的
   表情）。判断问的是「**有没有**」不是「有多少」，于是 54 个表情把 3621 个字符全部踢出快路径。

实测成本（`/bin/bash 3.2.57`，真的那段描述）：

```
整段量宽 (3620 字符)      0.479s
超过 576 格即停            0.132s     ← 3.6 倍
```

**`truncate_disp` 后面那个裁剪循环已经有早退**（`((w + CHAR_W > budget)) && break`），
**`wrap_print` 也不是问题**：它按**词**调 `disp_w`，而快路径是按词生效的 ——
URL 那些词全是纯 ASCII，一步就出。**所以整条链上唯一没有上界的就是第 2 步那一次调用。**

## 4. 逐项设计

### S2 —— 修法 B：有界早退（这是主修）

在 `truncate_disp` 里，把开头那次 `disp_w "$text"` 换成一个**有上界**的量宽：
累计宽度一旦超过 `max` 就停，直接判定「放不下」。

**这不是近似，是严格等价**：`char_w` 的取值域是 `{0,1,2}`，全部非负，所以累计宽度
**只增不减** —— 越过 `max` 的那一刻答案已经不可能反转，后面的字符不影响结论。

实现约束：
- 新写一个有界助手（如 `disp_w_capped`），**不动 `disp_w` 本身** —— 它还有别的调用点，
  改它就是把一次局部优化变成全局风险。
- 保留 ASCII 快路径：纯 ASCII 时仍然 `${#s}` 一步出。
- bash 3.2：累加写 `n=$((n + CHAR_W))`，**不写 `((n += CHAR_W))`**（宽度为 0 时
  算术命令返回状态 1，`set -e` 下会中止整个 TUI —— `disp_w` 头上那段注释就是为这个写的）。

### S3 —— 量完再决定 A

B 落地后重跑 §3 的端到端测量。**预期停顿落在 0.15–0.3 秒**，但这是推算不是实测：
0.88 秒里有 0.479 秒是那一次整段量宽，余下的是裁剪循环、两次换行遍历和章节块。

### S4 —— 修法 A：入口截短（条件项，**默认不做**）

`apply_item_info` 的 jq 读完整 `.description`，可以截成 `.description[:N]`。

**但证据说它大概率是噪声**：B 之后整条链上再没有对整段的遍历，
而 `wrap_print` 走的是已经裁到 `cut` 格的文本。A 省下的只是 bash 变量里多存几 KB。

**并且它有一个正确性边界**：一个静态的 `N` 在很宽的终端上会真的切掉内容 ——
`cut = 6 × (cols - 4)`，400 列时是 2376 格，`N=1200` 就不够了。

**决策规则（写死，免得下一个人凭感觉加）**：只有当 S3 量出 B 之后仍有 **≥100ms**
可归因于描述长度的成本时才做 A，且 `N` 必须 ≥ 3000 并在计划里写明它对应的终端宽度上限。
否则**明确不做**，理由记进 §5。
