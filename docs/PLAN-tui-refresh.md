## 目标

一屏之内，chrome 收到两端、内容占住中间；行的两个状态（**在播** 与 **光标**）第一次可以
同时、无歧义地看见；行数由一根轴管，且那根轴随列表模式切换。

实测基线（`tests/drive.sh -x 100 -y 30`，2026-09-01）：搜索列表 10 行内容 / 29 行可用，
章节列表 10 行。目标：**19 行 / 20 行**，内容占比 34% → 66%。

## 非目标

- **不做双列。** 这一版仍然是单柱，只是把柱子清干净。双列要重写宽度层的逐行合成与整个
  reflow，是另一个量级，等这版实拍出来再判断值不值。
- **不做连续滚动之外的第二个渲染器。** 两个列表模式共用 `display_list_menu` 的同一段代码，
  分支只在「窗口怎么算」和「哪根轴管扩缩」两处。`Tab` 曾经切的那个焦点卡不回来。
- **不碰 agent 面。** 两个新设置的 agent 面就是用户 config 里的键，和 `UT_KEYS` 一样 —— 
  这是「每个功能都要有 agent 面」那条规则对一个纯显示偏好的正确答案，不为它造第九个命令。

## 行的两个状态（贯穿 C 与整份计划的核心模型）

**两个状态正交，可以落在同一行。**

| 状态 | 是什么 | 怎么画 | 生命周期 |
|---|---|---|---|
| **在播** | 这一行就是播放器现在在放的东西 | **整行 inverse**（反白底块，跨满幅） | 由播放器决定；换页、换排序、改过滤都不丢 |
| **光标** | 用户当前指向哪一行 | 左侧 2 格槽位里的 `▶` + 标题 accent | 用户自由移动，`Enter` 让它变成「在播」 |

**在播不是按下标记的，是按身份匹配的。** 记 `CURRENT_PLAY_URL`，逐行比 `urls[i]`。
按 url 而不是按 index，是因为「不管在哪个 page」这句话要在**换排序（`o`）、换过滤（`/`）、
扩缩行数、切列表模式**之后仍然成立 —— index 在这四件事之后都会变，url 不会。

**章节视图是唯一的例外**，那里在播的那一行不是 url 相等，而是**播放头落在它的区间里**：
`start_time <= PT_POS_SEC < end_time`。原因是章节行的 url 带 `t=`，与 item 的 url 天然不等，
而 `chapter_pct` 已经在算这件事了，复用它。

**颜色关掉时 inverse 仍然在。** 反白是 SGR 7 / 背景属性，不是色相；`COLORS_ON=0` 掉的是
accent 的**颜色**，不是这一行的**底**。一个看不见「哪行在播」的无色终端，比一个没有色相的
终端糟得多。

## 实现约束（全局，八个条目都受它管）

这四条是 2026-09-01 冷读预检的产物（见文末「预检记录」）。它们不属于任何一个条目，
所以放在这里，而不是散在正文里 —— **上一轮那条循环依赖警告就是因为写成了散文才被脚注掉的。**

### 不变量 I-1 —— 测量高度 == 绘制高度

每个测量函数都是与它所预测的打印器**分开的**一段代码，这条不变量从来没被写下来过，
而 B / D / E 各会破它一次。三条硬规矩：

- **一个宽度常量，不要两个。** 进度条的宽度（B）、滚动条让出的格数（D）、状态段的右缘（E）
  必须全部从**同一个** `nav_cols` 派生式算出来，不是各算各的。B 的 bar 用旧分隔线的满宽、
  而 D 已经拿走 2 格 —— 这是最容易发生的一次超宽，且它的症状是折行，也就是多出一行
  测量不知道的高度。
- **凡是这份计划新画的字形，必须先进宽度表。** `char_w` 对不在表里的字符**一律返回 2**
  （`shell/uting:1787-1795`）。今天核过：D 的 `█` `│` 和 B 的 `╸` **三个都不在** `CW_NARROW`
  也不在 `CW_AMBIG`（`shell/uting:1746`），会被测成 2 格而终端画 1 格。落地时与当年加四个
  象限 spinner 字形同一个做法：先进表，再用。`━ ─ ● ▶` 已经在 `CW_AMBIG` 里，不用动。
- **右贴一律用 CHA，禁止算好的填充。** 时长轨早就用 CHA 解决了这个问题，理由写在
  `display_list_menu` 里：宽度层对非 ASCII 是**故意高估**的，填充会让右缘落在我们的测量
  说该落的地方，而不是终端真的画到的地方。E 的状态段是新的右贴，必须走同一条路。
  `GL_SEP`（`·`，U+00B7）是东亚歧义宽度，默认按 1 格算、`YT_AMBIG_WIDE=1` 按 2 格算 ——
  五个分隔符就是最多五格的偏差，正是 CHA 存在的场景。

### 不变量 I-2 —— 三段测量的非循环顺序

F 把 reflow 拆成三段之后，下带高度会依赖行预算也依赖的状态。现存代码已经解决过同构的问题
（详情块高度依赖选中行，而选中行依赖页几何），它的解法就是顺序，照抄：

```
  ① 先钳光标            —— 不需要任何页几何
  ② 为它测详情块        —— 需要光标，不需要行数
  ③ 由测得的 chrome 推 可见行数 / PAGE_SIZE
  ④ 由光标推 页 / VIEW_TOP
```

加两条硬约束：

- **下带的丢弃只能减少下带高度**，不得改变上带或任何已经测过的量。
- **键位块的内容只能依赖 宽度 / 列表模式 / 行源 / 引擎能力 / 播放器状态，不得依赖行数。**
  一旦它依赖行数，① – ④ 就不再是一条链而是一个环，单遍计算失效 —— 而在 100×30 上它每次
  都第一遍收敛，所以这个环不会在开发用的几何里露面。

### I-3 —— bash 3.2 的两口

- **新代码禁止 `((x -= y))` / `((x += y))` 作为语句。** 一律 `x=$((x - y))`。回收循环保持
  「从零件整体重算」的现有形式，不要改写成增量扣减：一个求值为 0 的算术命令返回状态 1，
  `set -e` 会在**重绘中途**杀掉进程 —— 备用屏还开着、光标还藏着、`stty -echo` 还生效，
  因为恢复它们的 trap 从没运行。失败形态是「终端死了」，而 `bash -n`、shellcheck 和离线套
  三个都看不见它。
- **按 URL 匹配在播行不得进内层循环。** 3.2 没有关联数组，逐行比对是每行、每次重绘一次
  平行数组扫描；而按字节读键意味着一次 CJK 按键是三遍读取、三次重绘。进渲染循环**之前**
  算一次 `PLAYING_IDX`（`CURRENT_PLAY_URL` 在 `urls[]` 里的下标，找不到 `-1`），循环里只比
  一个整数。

### I-4 —— 每一步的帧要和上一步的帧 diff

不是和**旧设计**逐字节比 —— 旧设计正是这八个条目要删掉的东西，对着它证明「没变」是给一帧
没人会看见的画面做公证。是和**上一步**比：两份 capture 本来就有，`diff` 免费，抓的是
「我顺手还动了别的」。差异必须**恰好**是这一步声明要改的东西。

**配方（H 这一步摸索出来的，往后六步照用）。** 裸 diff 会被两种噪声淹掉，两种都不是改动：

- **表头图标每次启动掷一次硬币** —— `shell/uting:1308`，`YT_ICON` 未设时 `♫ ` / `🎧` 各半，
  `:613` 的 usage 有明文。**每一次抓帧都 `YT_ICON=phones`**，否则第 2 行永远在闪。
- **结果行是活数据** —— 两次搜索之间 YouTube 的排序、条数、播放量计数都会变。**只 diff chrome**：
  `grep -vE '^ *[0-9]+\. |views ·|次播放|drive\.sh:'` 两边各过一遍。

上一步的基线用 `git worktree add tmp/base-head HEAD` 起一份，两边各跑一次 `tests/drive.sh`，
跑完 `git worktree remove tmp/base-head`。**不要 `git stash`** —— 一个中途被打断的 stash
会把半份改动留在树里，而这份计划要连做七步。

## 逐项实现规格

### A —— 删掉两条满幅 rail

两个调用点，都在 `shell/uting`：

- `display_list_menu` 里键位块下面那条（`card_divider "$nav_cols"` / `render_prog_bar`，
  今天 `shell/uting:3423`）—— **整段删除**。它在播放时兼任进度条，那件事由 B 接走。
- `print_details` 开头那条（`shell/uting:2367-2374`）—— **整段删除**，但它**不是一条纯分隔线**：
  在章节视图里 `chapter_pct` 有值时，它画的是**光标所在那一章的进度**
  （`render_prog_bar "$CHAP_PCT"`）。删它会丢一个真事实，所以必须与 B 成对做 —— B 用整片
  bar 上的区间括号接走它。删除后 `DETAIL_LINES` 的种子从 `1` 改成 `0`。

分带改为**一个空行**，chrome 靠 dim 与位置区分。

**删完 grep-gate `card_divider` 与 `DIV_STR`**（今天定义在 `shell/uting:1687-1695`）：
若再无调用方，连定义一起删；`GLYPH_RUN` / `repeat_glyph` 被 B 继续用，留着。
这是 A→E 的 C 步，放最后做。

### B —— 进度条变回一个进度条

一条独立的行，**只在 `CURRENT_PLAY_ID` 非空时存在**，坐在 Now-Playing 横幅正下方，
左缩 2 格（与行的 2 格槽位对齐），宽 `nav_cols - 4`。

`render_prog_bar`（`shell/uting:2149`）改三态输出：已播 `━`、播放头 `╸`、未播 `─`；
ASCII 降级 `=` / `>` / `-`（今天的 ASCII 播放头是 `#`，一并换成 `>`）。今天的 `●` 头去掉 —— 它在 4% 处读起来像横线上一粒灰。

**章节视图额外画区间括号，括号标的是「光标所在的那一章」，不是在播那一章。**
在同一条 bar 上，把 `[start_time/duration, end_time/duration]` 两个格位改写成 `[` 与 `]`
（ASCII 降级同形）。区间宽度不足 2 格时只画 `[` 不画 `]` —— 一个 1 格的 `[]` 是噪点。

**为什么是光标那一章而不是在播那一章**：在播那一章已经由**整行 inverse** 说了（见下面的
行状态模型），bar 上再说一遍是重复；而「光标指着的这一章在整片里的什么位置、有多长、
播放头到没到它」今天正是被删掉的那条 rail 在回答的问题。所以这是**接走**，不是丢弃：

- 光标停在在播那一章（打开视图时的默认）→ 播放头 `╸` 落在括号**内**，与今天同义；
- 光标移到后面某一章 → 括号跑到播放头**右边**，读作「那一章在这儿，还没放到」——
  比今天那条空的章节 bar 说得更多；
- 光标移到已经放过的一章 → 括号在播放头**左边**，读作「放过了」。

`chapter_pct`（今天只服务那条 rail）落地后 grep-gate：区间括号要的是 start/end 的**分数**，
不是一个百分比，多半用不上它了。

**时间只出现一次。** 横幅右端的 `elapsed / total` 保留；今天横幅和 rail 各有一份位置读数，
这次由 bar 承担「在哪」，横幅承担「多少」，不重复。

### C —— `▶` 光标 · 在播行 inverse · 编号一键开关

**1. 光标标记。** 2 格槽位：光标行 `▶ `，其余 `  `。ASCII 降级 `> `。
槽位宽度不变（今天也是 2），标题列不移动。

**新建 `GL_CURSOR`，不要复用 `GL_PLAY`。** 两者今天恰好同形（`▶` / ASCII `>`），但它们是
两个事实 —— 一个是「光标在这儿」，一个是「播放器在放」。共用一个名字，将来想让其中一个
换字形就得先做一次拆分，而那正是这次要清掉的那类耦合。

**2. 在播行 inverse。** 画法是 **先铺底、再跳列**，这是唯一能让 CHA 跳过的那段空白也带上
底色的顺序：

```
  printf '\033[K'                 # 先擦掉上一帧（默认底），这一步和今天一样
  printf '%s' "$C_ROW_HL"         # 开底色 / 反白
  printf '%s%s' "$gutter" "$title"
  printf '\033[K'                 # ← 关键：带当前底色擦到行尾（BCE），把中间那段空白铺满
  printf '\033[%dG%s' "$rail_col" "$rail"
  printf '%s\n' "$C_RESET"
```

第二个 `\033[K` 依赖 BCE（back-color erase）。xterm / iTerm2 / Terminal.app / kitty /
alacritty / tmux 都有。**没有 BCE 的终端退化成今天的样子**（中间那段不铺底），是降级不是崩。

**但今天的 `assert_pane.py` 永远证明不了这一条。** 它读的是 `tmux capture-pane -p`
（它自己的文档就这么写），而 `-p` 不带 `-e` 会把 SGR 全部丢掉 —— 一帧反白只铺到标题、
槽位空着的画面，在它眼里和正确的画面一模一样。所以 C 落地时要给 `assert_pane.py` 加一个
**新断言**（加断言，不加文件）：用 `tmux capture-pane -pe` 再抓一次，断言在播那一行的
SGR 区间**从第 1 列覆盖到第 `nav_cols` 列**。这是这次唯一一个「工具对新 bug 结构性失明」的
地方，值得为它扩一次工具。

**`PLAYING_IDX` 在渲染循环之前算一次**，见 I-3 第二条。

**不要**改用「算好空格填充」来铺底：那正是 CHA 存在的理由 —— 宽度层对非 ASCII 是**故意高估**的，
填充会让时长轨在数学粗体字母那类标题上左偏 ~5 列，毁掉全屏唯一一条要被纵向扫读的列。

**3. 编号开关。** 新键 `#`（连同全角 `＃` 一起绑，与 `?`/`？` 同例）。开时行前多一个
右对齐的 dim 编号字段，宽 `${#NUM_ENTRIES}`，**不带点**（`1.` 那个点是年代记号）；关时那个字段
连同它的一个分隔空格一起不占格。默认 **关**。

新偏好键 `UT_ROW_INDEX=on|off`，进 `PREF_KEYS`（`shell/uting:56`），走 `mark_pref` 写回。

### D —— 两个列表模式，一键切换；`●○○○` 永久消失

**`UT_LIST_MODE=scroll|page`，默认 `scroll`。切换键 `Tab`。**
`Tab` 今天是明确无绑定的（`AS-BUILT-tui.md` 有一句专门说它随第二个渲染器一起退役），
现在它有东西可以够了。进 `PREF_KEYS`，写回。

**每个模式里，「扩/缩行数」只有一根轴管 —— 这是 `m`/`M` 当年退役的同一条理由。**

| | `scroll`（默认） | `page` |
|---|---|---|
| 窗口 | `VIEW_TOP` = 首个可见行的绝对下标 | 今天的 `PAGE_SIZE` / `NUM_PAGES` / `page` |
| `↑`/`↓` | 移光标，窗口跟着光标滚 | **只在本页内移光标，到本页顶/底就停住，不跨页** |
| `↑` 在**全表第 0 行** | → `fewer_results()` | 无（原地不动） |
| `↓` 在**全表最后一行** | → `more_results()` | 无（原地不动） |
| `←`/`→` | **静默 no-op**（没有页可翻） | 翻页；第 1 页再 `←` → `fewer_results()`，末页再 `→` → `more_results()` |
| 状态段 | 无页码 | 多一段 `页 3/4` |

`more_results()` / `fewer_results()`（`shell/uting:4763` / `4805`）**函数本体不动**，
只换调用方 —— 和当年 `m`/`M` 退役时一样。

**滚动条 gutter，两个模式都有，永远在最右一列。** 每个可见行一格：
`█`（拇指）/ `│`（轨），ASCII 降级 `#` / `|`。
拇指长度 = `round(可见行数 × 可见行数 / NUM_ENTRIES)`，至少 1；
起点 = `round(可见行数 × 首个可见行下标 / NUM_ENTRIES)`，钳进 `[0, 可见行数 - 拇指长]`。
`NUM_ENTRIES <= 可见行数` 时整列画 `│`。

**时长轨为它让出 2 格**：`row_w` 的算式从 `nav_cols - iw - 1 - 2 - rail_w` 改为
`nav_cols - iw - 1 - 2 - rail_w - 2`，CHA 的目标列从 `nav_cols - rail_w + 1` 改为
`nav_cols - rail_w - 1`。

**`●○○○` 那一行整段删除**（`shell/uting:3632-3648`，含 `NUM_PAGES > 1 && dots_ok` 的门
与它的文本降级分支 `page $page/$NUM_PAGES`）—— 页码进 E 的状态段。
`GL_DOT` / `GL_DOT_OFF` 在那一段之外**没有第二个调用方**（已 grep 核过），
所以连同 `shell/uting:1266` 与 `:1291` 两张字形表里的定义一起删。
`dots_ok` / `dots_owed` 这两个 reflow 变量也随之退役 —— 它们的整个职责就是给这一行留位。

**存储行源（歌单 / 历史 / 分P / 章节）没有「更多」可取**，所以在这四个行源下，
`scroll` 模式的两端和 `page` 模式的两端一样：原地不动，不出提示。这条今天已经成立，只是
现在多了一根轴要遵守它。

## 边界情况

1. **在播的那一行被过滤掉了**（`/` 收窄后它不在 `ALL_ROWS` 的可见集里）—— inverse 不画，
   横幅照旧。不为它保留一行，不出提示。
2. **在播的那一行不在当前窗口里** —— 不画，也**不**自动滚过去。光标是用户的，窗口跟着光标。
3. **光标行就是在播行** —— 两个状态叠加：`▶` + accent 标题 + 整行 inverse。这是常态
   （`Enter` 之后的第一帧就是），不是特例。
4. **列表为空**（`NUM_ENTRIES == 0`）—— 滚动条整列不画（不是画空轨），今天那条
   `S_NO_MATCH` 提示原样。
5. **`scroll` 模式下 `←`/`→`** —— 静默，不出「此处不适用」的提示：一个测量过的块不为说「不」
   花一格，这条规矩对提示行同样成立。
6. **`Tab` 切模式时光标不动。** 切到 `page` 时页码由光标推出（`selected / PAGE_SIZE + 1`）；
   切回 `scroll` 时 `VIEW_TOP` 由光标推出，保证光标可见。跨模式的锚是**用户看着的那一行**，
   和今天 resize 重分页时的锚是同一个。
7. **一行都放不下的终端** —— 今天那条「行的地板是 1，丢无可丢时诚实溢出」原样保留。
8. **`UT_ROW_INDEX=on` 且 `NUM_ENTRIES` 跨进三位数** —— 编号字段宽度由 `NUM_ENTRIES` 定，
   不由页定，翻页/滚动时不移动。这条今天已经成立，改动后要继续成立。

## 施工顺序

**按「这一步把 chrome 变高还是变矮」排，不按「哪一步动了骨架」排。**

reflow 唯一要防的失败是**表头滚出屏幕**，而那只会被**变高**的一步制造出来。按高度影响分类：

| | 高度影响 |
|---|---|
| H | 0（只换键位绑定） |
| G | **−1 到 −3**（详情块标题是折行打印） |
| A + B | **−1**（空闲）／ **0**（在播：删掉的 rail 就是那条 bar） |
| C | **0**（槽位本来就 2 格，反白是纯 SGR） |
| E | **−1 或 0**（状态并进标题行，装不下就退回自己一行） |
| D | **−1**（删 dots；gutter 是宽度不是高度） |
| **F** | **0，但重排高度是怎么算出来的** |

七项里六项单调减少或不动 chrome —— 它们**不可能**制造那个失败。只有 F 在不改净高度的前提下
改变结构。所以 F 排**最后**：到那一步 chrome 最瘦、预算最松，前面六步的帧都已经拍过，
出问题就是它，不用二分。

```
  1. H   音量搬 -/= + 数字跳行           ← 零布局风险，最小，先热身
  2. G   详情块去掉重复标题              ← 每一步都在腾预算，不是花预算
  3. A+B 删两条 rail + 独立进度条        ← 成对做：A 单独做会在章节视图丢掉一个真事实
  4. C   ▶ 光标 + inverse 在播行 + 编号开关（含 assert_pane.py 的 -pe 新断言）
  5. E   状态段（右贴走 CHA，见 I-1）
  6. D   两个模式 + gutter + 删 dots     ← 导航语义换轨；新字形先进宽度表，见 I-1
  7. F   键位带下移 + 三段测量           ← 最后，且是唯一需要 I-2 那条顺序的一步
  8. grep-gate 后删死代码：card_divider / DIV_STR / GL_DOT / GL_DOT_OFF /
        chapter_pct（若真无调用方）/ dots_ok / dots_owed
  9. 文档重新同步（七处「八个键」→「十个键」+ AS-BUILT-tui.md 里剩下的三处 9/0 键位 +
        AS-BUILT-tui.md 的渲染模型章节与那句「Tab 随第二个渲染器一起退役」）
```

**「D 和 F 都动 reflow，必须先做，否则预算要算两遍」——这条理由是错的，已撤回。**
预算是运行时每次重绘都在算的；算两遍的是作者，不是代码。

每一步一个 commit，每一步跑 V1 + V2 + V3（帧 diff）。必拍集 P1–P9 在 **4、6、7** 之后各跑
一整轮 —— 三轮，不是九轮。

**F1 被否决的理由，记在这里，因为它同时是施工顺序改变的理由。**
原方案是把 F 拆成「先做一次视觉逐字节不变的重构，diff 证明没变」。它无用：

**I-4**，但比对的对象从「旧设计」换成「上一步」。
